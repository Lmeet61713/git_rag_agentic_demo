# 检索能力问题分析与改进计划

> 状态：第二轮改进已实施，剩余真实模型与端到端验收  
> 最近更新：2026-08-06  
> 关联文档：[08-交接日志.md](08-交接日志.md)、[10-验收标准.md](10-验收标准.md)

## 1. 现象

用户提问“帮我检索一下那几个项目仓库用来vue架构？”，Agent 回答“未找到使用 Vue 架构的项目仓库”，并列出 `Lmeet61713/I-former` 的 Python 文件作为来源。

实际索引中存在：

- `Lmeet61713/YueDu` 有 14 个 `.vue` 文件。
- `Lmeet61713/YueDu/PROJECT.md` 明确写着“前端：Vue 3 + Vite + Element Plus + Pinia + Vue Router 4 + Axios”。

因此答案是错的，错误来自检索证据本身，而不是模型总结能力。

## 2. 当前数据验证

使用当前 SQLite 向量数据直接执行检索：

- 查询“帮我检索一下那几个项目仓库用来vue架构？”时，前 8 条结果中有 7 条来自 `Lmeet61713/YueDu` 的 `.vue` 文件，另有一条 `PROJECT.md`。
- 这说明当前索引里已经有正确的 Vue 数据，当前查询可以召回。
- 被保存的旧回答来源则是 `Lmeet61713/I-former` 的 Python 文件，分数约 `0.33`，属于低置信度、错误召回的旧结果。

结论：旧回答发生时检索链路返回了错误证据；当前索引数据本身是完整的，但检索链路仍不稳定。

## 3. 当前已实施改进（2026-08-06）

1. 接入真实语义索引。
   - 使用 ONNX `BAAI/bge-small-zh-v1.5`（512 维），未配置时回退 Hash。
   - 使用 Chroma 持久化向量，6 个仓库已重建，当前 4697 条向量。
2. 建立项目级技术栈摘要索引。
   - 建库时生成 `project_summary`，覆盖 README、package 清单、语言统计和目录结构。
   - `repo_tech` 工具专门回答“哪个仓库用 Vue/FastAPI”类问题。
3. 改造混合检索。
   - 由“向量 top-24 内重排”改为“向量候选 + 独立关键词/路径候选”并集融合。
   - 引入 `jieba` 中文分词。
   - 增加 `search_min_score` 和首名差距过滤。
4. 接入 LangGraph 状态流。
   - 路由 → 检索 → 反思 → 回答的骨架已存在。
   - 使用 Pydantic `ToolSelection` 让 LLM 结构化选工具。
   - 增加 `project_intro` 和非检索意图强制兜底。
5. 前端同步。
   - 聊天支持 Markdown、来源摘要、SSE 逐 token 流式。
   - 侧边栏展示当前模型并支持快速切换。
6. 增加非仓库闲聊输出越界校验。
   - 新增 `general_chat` 工具；天气、闲聊、个人问题等即使触发检索，也会在 validate 阶段清空检索证据，不展示仓库内容。
7. 增加检索后重排与纠错。
   - 召回结果先按语义分与词面相关度融合重排，低相关证据直接过滤。
   - 新增 validate 节点；模型可用时做 LLM 相关性校验，无证据时进入重试或明确未找到。
   - 检索为空或证据不足时支持放宽项目/文件类型并重试，最多 3 轮。
8. 修复显式项目跨项目污染。
   - 用户明确指定 `owner/repo` 时，无结果重试不再放宽项目过滤，避免返回其他仓库内容。
   - `image_search`、`doc_search` 等专用检索不降级为其他文件类型。
   - 长期记忆改为中文分词召回并按项目隔离；聊天历史持久化工具与模式。

## 4. 根因分析

| 根因 | 说明 |
|------|------|
| Hash fallback embedding | 当前使用 64 维 Hash 向量，只统计词频映射，没有语义理解能力。词之间容易撞桶，低质量向量会让无关代码排到前面。 |
| 查询类型与索引粒度不匹配 | “哪个仓库用 Vue”是项目级技术栈问题，但当前只在代码块层面做向量检索，没有“仓库语言/技术栈摘要索引”。 |
| 缺少项目级元数据工具 | 虽然已有 `repo_meta` 能回答“最早/最近/哪个仓库”，但还不能按“技术栈/语言”筛选仓库。 |
| 低分结果未过滤 | 旧回答使用分数约 `0.33` 的结果，仍被当作证据传给模型。没有置信度阈值，也没有与第一名分数的差距判断。 |
| LLM 只能信任检索证据 | 提示词要求模型基于检索结果回答；当检索证据错误时，模型会给出看似合理但错误的结论。 |
| 尚未接入真实语义模型 | ONNX/Chroma 未启用，真实语义 embedding 和持久化向量库仍待接入。 |
| 尚未接入 LangGraph 多步拆解 | 当前工具选择是规则优先，还没有真正让模型按 CoT 拆解“项目级问题 -> 元数据筛选 -> 代码检索”。 |

## 5. 改进计划（实施情况）

1. 建立仓库级技术栈/语言摘要索引。
   - 从 `indexed_files` 的语言统计生成仓库技术栈摘要。
   - 解析 `package.json`、`requirements.txt`、`pyproject.toml`、`go.mod` 等清单。
   - 新增 `repo_tech_search` 工具，专门回答“哪个仓库用 Vue/Python/FastAPI”这类问题。

2. 检索质量保护。
   - 为向量结果增加最低置信度阈值和相对分差过滤。
   - 对项目级问题优先走仓库元数据/技术栈工具，不走代码块向量检索。

3. 接入真实语义索引。
   - 安装并验证 ONNX embedding。
   - 安装并验证 Chroma，替换 SQLite 向量兜底。

4. 接入 LangGraph 状态流。
   - 让模型按 CoT 拆解任务：判断问题类型 -> 选择工具 -> 执行 -> 汇总。
   - 支持多轮工具调用和失败重试。

5. 建立检索黄金用例测试。
   - 至少覆盖：“哪个仓库用 Vue”“最早代码库”“README 安装步骤”“图片检索”。
   - 对返回结果做项目级断言，避免只断言“有结果”。

6. 增加非仓库闲聊输出越界校验。已完成。
   - 新增 `general_chat` 工具，天气、闲聊、个人问题等不进入最终输出。
7. 增加检索后重排与纠错。已完成。
   - 召回结果先做相关性判断，无关证据直接丢弃。
   - `reflect` 不再只处理“无结果”，也要处理“有结果但无关”。
8. 回答前最终校验。已完成。
   - 如果最终没有可用结果，直接回答或说明未找到，不再展示来源。

## 6. 本轮结论

- 第一轮修复已完成：ONNX、Chroma、项目级技术栈摘要、并集混合检索、置信度过滤、LangGraph 骨架、`project_intro`。
- 第二轮修复已完成：`general_chat` 输出越界校验、检索后重排、LLM 相关性校验、validate 节点与多轮重试。
- 第三轮修复已完成：显式项目检索不再跨项目兜底，图片/文档专用检索不降级；聊天历史工具/模式持久化；长期记忆中文召回与项目隔离。
- 真实数据已验证显式项目图片检索、项目概述与长期记忆中文召回；剩余工作是真实模型问答、图生文真实 API 与浏览器端到端验收。
