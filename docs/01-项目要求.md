## 1. 项目概述

MyAgentic 是一个本地单用户、面向 GitHub 公开仓库的 Agentic RAG 系统。用户通过浏览器使用 GitHub 登录，选择需要了解的公开仓库，系统在本地完成同步、解析、向量化，并在聊天界面中让 Agent 跨项目检索代码、文档和图片，回答必须带来源。

一句话定位：

> 把用户自己的 GitHub 公开项目变成可对话的本地知识库。

## 2. 用户画像与典型场景

目标用户是个人开发者，希望在本地快速理解自己维护或关注的多仓库代码。

| 编号 | 场景 | 期望结果 |
|------|------|----------|
| S1 | 用户想确认所有公开仓库当前的状态 | 登录后看到仓库列表、已入库/未入库/索引中状态 |
| S2 | 用户想了解某个项目大致包含什么 | Agent 返回项目概览、README 摘要和文件树 |
| S3 | 用户想查某个功能在哪里实现 | Agent 检索代码并返回文件路径、函数和原文片段 |
| S4 | 用户想查文档里的安装说明 | Agent 检索文档并返回章节和来源 |
| S5 | 用户想找登录页截图或 logo | Agent 检索图片描述并返回本地图片预览 |
| S6 | 用户想跨项目搜索同类实现 | Agent 跨项目、跨类型检索并汇总 |

## 3. 范围界定

### 3.1 本阶段范围（MVP）

- 只处理 GitHub 公开仓库。
- 用户手动选择仓库入库，不自动建库。
- 系统只做检索和问答，不修改代码、不提交 commit、不推送 PR。
- 本地单用户运行，数据默认保存在本地。
- 异步任务优先使用 FastAPI 后台任务，不引入 Redis。

### 3.2 暂不实现

| 能力 | 说明 | 预期时间 |
|------|------|----------|
| 私有仓库 | 需要额外申请 repo scope | 后续阶段 |
| 自动建库 | 监听仓库变化后自动入库 | 后续阶段 |
| 自动改代码 | 生成补丁、commit、PR | 暂不规划 |
| 多用户 | 预留 user_id，但不实现多租户 | 后续阶段 |
| 仓库自动更新 | 定时拉取仓库更新 | 后续阶段 |

## 4. 功能需求

优先级定义：P0 为 MVP 必须；P1 为 MVP 后尽快补充；P2 为扩展项。

### 4.1 GitHub 登录（P0）

功能：

- 使用 GitHub OAuth App 登录。
- 后端保存会话状态，支持退出登录。
- 仅申请公开仓库所需的最小权限。

验收标准：

- 用户点击登录后跳转 GitHub 授权页，授权后回到本地应用。
- 刷新页面后登录状态仍然有效。
- 退出登录后无法访问仓库列表和聊天页面。

### 4.2 仓库列表与入库状态（P0）

功能：

- 分页拉取用户所有公开仓库。
- 与本地索引状态合并。
- 展示“已入库”“未入库”“索引中”三种状态。
- 支持刷新仓库列表。

验收标准：

- 未入库仓库显示红色“入库”标签。
- 索引中仓库显示实时状态。
- 已入库仓库可查看上次索引时间和 commit。

### 4.3 异步建库（P0）

功能：

- 用户手动触发入库、重新入库、删除入库。
- 每个仓库有独立任务状态和阶段进度。
- 任务失败保留错误信息，支持重试。

验收标准：

- 入库期间前端不阻塞。
- 能展示 cloning、scanning、parsing、embedding、writing 阶段。
- 删除入库后向量和镜像被清理，仓库回到未入库状态。

### 4.4 向量检索（P0）

功能：

- 支持按项目过滤、按文件类型过滤。
- 支持代码、文档、图片描述三类召回。
- 支持跨项目检索。
- 返回内容、来源路径和相似度。

验收标准：

- 指定项目检索只返回该项目内容。
- 跨项目检索能返回多个仓库的结果。
- 图片检索返回图片路径和描述。

### 4.5 Agent 问答（P0）

功能：

- 使用 LangChain 和 LangGraph 编排。
- 支持 DeepSeek 和阿里云模型，可在前端切换。
- 支持工具调用和多轮检索。
- 回答必须给出检索来源。

验收标准：

- 无法从索引找到答案时明确说明，不编造来源。
- 追问时能利用会话上下文。
- 模型服务商切换后能正常问答。

### 4.6 记忆系统（P1）

功能：

- 短期记忆保存当前会话上下文。
- 长期记忆保存用户偏好和项目事实。
- 记忆按 user_id、project_id 隔离。
- 支持记忆的写入、检索、更新、删除。

验收标准：

- 同一会话的追问能理解上下文。
- 长期记忆不会把摘要当成真实代码内容。
- 记忆召回有数量上限，不全部塞入提示词。

### 4.7 前端界面（P0）

功能：

- 页面包括登录页、仓库列表页、聊天界面、模型配置界面。
- 聊天界面展示回答、来源、代码块和图片预览。
- 模型配置支持输入和更换 API Key。

验收标准：

- 页面在桌面浏览器可用，状态反馈清晰。
- API Key 只在密码框中输入，不保存在浏览器本地。

### 4.8 模型配置（P0）

功能：

- DeepSeek 和阿里云模型名可配置。
- API Key 由后端加密保存。
- 模型调用失败时前端有明确错误提示。

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| 数据 | 所有数据默认保存在本地；向量库在 storage/chroma，仓库镜像在 data/repos，元数据在 SQLite |
| 安全 | .env 不入库；API Key 和 GitHub token 加密保存；日志不打印密钥 |
| 可靠性 | 单个仓库索引失败不影响其他仓库；任务状态持久化，重启后可恢复 |
| 性能 | 本地模型推理优先；大仓库有大小限制和忽略规则；聊天支持流式输出 |
| 可维护性 | 模块职责清晰；文档与代码同步更新；统一编码 UTF-8 |
| 可扩展性 | 数据模型预留 user_id；向量库按 project_id 逻辑隔离，后续可拆分 collection |

## 6. 端到端验收流程

1. 用户配置 .env 中的 GitHub OAuth 和模型信息，启动后端与前端。
2. 用户通过浏览器完成 GitHub 登录。
3. 仓库列表展示用户公开仓库及入库状态。
4. 用户选择一个仓库点击“入库”，前端看到阶段进度。
5. 入库成功后，用户在聊天界面询问项目功能、文档内容或图片资源。
6. Agent 返回带来源的回答，来源可跳转到本地文件或展示图片。
7. 用户配置模型服务商和 API Key，问答仍然可用。

## 7. 术语表

| 术语 | 说明 |
|------|------|
| 入库 | 将一个 GitHub 仓库同步到本地并建立向量索引 |
| 镜像 | 仓库在 data/repos 下的本地克隆 |
| 索引状态 | pending/running/success/failed |
| 项目概览 | 由 README、文件树、项目元数据生成的概要信息 |
| 短期记忆 | 当前会话内的问题和回答上下文 |
| 长期记忆 | 跨会话保存的用户偏好和项目事实 |
