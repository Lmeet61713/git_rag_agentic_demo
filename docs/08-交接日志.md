## 5. 交接启动方式

后端：

```bash
cd E:\mmmmmmmmmmmmmmmm\MyAgentic
uv sync
uv run python -m backend.app
```

必须在普通终端中启动，不能放在无法访问外网的沙箱里；启动前先确认 8000 端口没有旧后端进程。

前端：

```bash
cd E:\mmmmmmmmmmmmmmmm\MyAgentic\frontend

npm run dev
```

启动后必须使用 `http://127.0.0.1:5173` 访问前端；不要使用 `localhost`，否则 GitHub OAuth 的 state 会话仍会不匹配。

测试：

```bash
cd E:\mmmmmmmmmmmmmmmm\MyAgentic
uv run pytest
uv run ruff check backend
```

## 6. 关键配置

- .env：GitHub OAuth、会话密钥、加密密钥、模型配置。
- GITHUB_CALLBACK_URL：`http://127.0.0.1:8000/api/auth/callback`，必须与 GitHub OAuth App 一致。
- 前端 Vite 代理：`/api` 转发到 `http://127.0.0.1:8000`。
- 登录请求不走 Vite 代理，直接请求 `http://127.0.0.1:8000/api/auth/login`，保证 state 会话 cookie 与回调同 host。
- 数据目录：data/；向量目录：storage/chroma/。

## 8. 注意事项

- `.env` 包含真实 GitHub Client Secret，不要提交到 Git，也不要贴到日志或聊天记录中。
- Python 版本锁定 3.13；如引入新依赖需执行 `uv sync`。
- Hash fallback embedding 维度为 64；接入 ONNX 后需固定维度再创建 Chroma collection。
- 当前 Chroma 未安装，向量检索走 SQLite 兜底，适合开发验证，不适合大数据量。
- 后端必须能访问 `https://github.com`；否则 OAuth 回调会在换 token 时连接失败。
- 当前暂停在阶段 1 真实浏览器登录重测，确认成功后继续阶段 2-10 联调。
