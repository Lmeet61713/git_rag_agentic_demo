## 1. 技术选型总览

| 层次 | 选型 | 定位 | 备选/后续 |
|------|------|------|-----------|
| Python 管理 | uv | 依赖、虚拟环境、脚本入口 | 无 |
| 后端 | FastAPI + Uvicorn | REST API、SSE、后台任务 | 无 |
| 数据访问 | SQLAlchemy 2 + aiosqlite | SQLite 元数据、异步访问 | sqlite-utils（不推荐） |
| 向量库 | Chroma | 本地持久化向量检索 | 后续可评估 Qdrant |
| Embedding | 本地 ONNX 文本模型 | 离线向量化，不依赖外部 API | sentence-transformers |
| Agent | LangChain + LangGraph | 工具调用、状态流、记忆 | 无 |
| LLM | DeepSeek / 阿里云 DashScope / 本地 Ollama | Agent 推理和回答 | 可扩展其他 OpenAI 兼容服务 |
| 图片描述 | 阿里云图生文 API | 图片转文字描述 | 可扩展其他多模态服务 |
| 前端 | Vue 3 + Vite + Element Plus | 浏览器界面 | 无 |
| 状态管理 | Pinia + Vue Router | 前端状态与路由 | 无 |
| HTTP | Axios + SSE | 接口调用、流式回答 | EventSource/fetch |
| 测试 | pytest / Vitest | 后端与前端测试 | Playwright 可选 |
| 代码质量 | ruff | 格式化与 lint | 无 |

## 2. 后端技术栈

### 2.1 Python 与 uv

- Python 3.13，由 pyproject.toml 锁定。
- 使用 `uv sync` 安装依赖，`uv run python -m backend.app` 启动。
- 若某些库与 Python 3.13 不兼容，评估回退 3.12 并同步修改 pyproject.toml。

### 2.2 FastAPI

- REST API 使用 Pydantic 校验请求和响应。
- 聊天回答使用 SSE 流式输出，避免前端长时间等待。
- 异步入库使用 FastAPI BackgroundTasks，任务状态写入 SQLite。

### 2.3 数据访问

- 选 SQLite + SQLAlchemy 2 + aiosqlite，不选 sqlite-utils。
- 理由：类型化 ORM、事务管理、后期迁移到 Alembic 更顺畅。
- 数据库文件默认放在 data/app.db。

### 2.4 向量库 Chroma

- 使用 PersistentClient，数据目录 storage/chroma。
- 主 collection 名称为 myagentic。
- 相似度使用 cosine。
- 一个 collection 内通过 metadata 逻辑隔离项目；字段值只支持标量，不嵌套。
- collection 的向量维度在创建时确定，之后不可修改，初始化时必须固定 embedding 维度。

### 2.5 Embedding

- 第一版没有专用代码向量模型，使用本地 ONNX 通用文本 embedding。
- 复用 local_onnx_embedding_core.py 的加载和推理模式。
- 模型路径通过 EMBEDDING_MODEL_PATH 配置。
- 实现阶段优先验证中文效果较好的 bge 系列模型，具体型号和维度在代码阶段确认。
- 代码块向量化前拼入文件路径、语言、函数/类名、关键注释和代码内容。

### 2.6 Agent

- LangChain 负责模型接入和工具封装，LangGraph 负责 Agent 状态流。
- 统一 LLMClient 适配层，屏蔽 DeepSeek、DashScope 与 Ollama 的接口差异。
- 工具规划：search_code、search_docs、search_images、read_file、list_files、project_overview。

### 2.7 图片描述

- 使用阿里云 DashScope 图生文能力（qwen-vl 系列），具体模型名以官方文档为准。
- 图片描述结果落库缓存，避免重复调用和重复计费。
- 图片原文件保留在本地镜像，Chroma 只存描述、路径和元数据。

### 2.8 代码质量与测试

- 后端使用 ruff 做格式化和 lint。
- 测试使用 pytest、pytest-asyncio、httpx AsyncClient。
- 关键覆盖：OAuth 会话、任务状态机、文件解析、检索过滤、Agent 工具、记忆读写。

## 3. 前端技术栈

- Vue 3 + Vite，使用 `<script setup>`。
- Element Plus 提供登录、仓库列表、聊天窗口、表单组件。
- Pinia 管理登录态、仓库列表、会话状态；Vue Router 管理页面路由。
- Axios 调用 REST API；SSE 接收 Agent 流式回答。
- 图片和文档来源通过后端 /api/files 路由访问本地镜像。
- 测试使用 Vitest + Vue Test Utils；包管理器推荐 pnpm，环境不便时用 npm。

## 4. 模型配置

### 4.1 服务商适配

| 服务商 | 接入方式 | 默认端点 | 模型 |
|--------|----------|----------|------|
| DeepSeek | OpenAI 兼容 | https://api.deepseek.com | 用户配置 |
| 阿里云 DashScope | OpenAI 兼容 | https://dashscope.aliyuncs.com/compatible-mode/v1 | 用户配置 |
| 本地 Ollama | 原生 /api/chat | http://127.0.0.1:11434 | 本机已安装模型 |
| 图生文 | DashScope 原生多模态 API | 以官方文档为准 | qwen-vl 系列 |

说明：

- 模型名不写死，通过 .env 或前端配置保存。
- 当前文档不承诺具体模型名称，以服务商 API 官方文档为准。
- 后端需要统一适配层，保证切换服务商不改变 Agent 逻辑。

### 4.2 API Key 处理

- 前端使用密码输入框，显示为 `*`。
- API Key 不保存在浏览器本地存储，发送到后端加密保存。
- 使用 cryptography 加密，密钥来自 .env 的 APP_SECRET_KEY。
- 日志输出前对密钥和 token 做脱敏。
- 更换 API Key 时清除旧配置。

## 5. 数据存储规划

### 5.1 本地目录

```text
storage/chroma/                     # Chroma 持久化
data/repos/<owner>/<repo>/          # 仓库镜像
data/app.db                         # SQLite 元数据
.env                                # 本地配置，不提交
```

### 5.2 SQLite 表

- users：GitHub 用户信息
- repos：仓库元数据、索引状态
- index_jobs：入库任务状态
- files：已索引文件清单
- chat_sessions / chat_messages：会话和聊天记录
- memory_entries：长期记忆
- model_configs：模型服务商与加密 API Key

### 5.3 Chroma metadata 字段

```text
project_id
owner
repo
path
file_type
language
symbol
commit_sha
file_hash
chunk_index
```

字段规则详见 [05-向量数据库设计.md](05-向量数据库设计.md)。

## 6. 异步任务方案

第一版：

- FastAPI BackgroundTasks 执行入库任务。
- 任务状态持久化到 SQLite，重启后 failed/pending 任务可重新发起。
- 任务状态：pending、running、success、failed。
- 任务阶段：cloning、scanning、parsing、embedding、writing。

演进路径：

- 仓库规模或任务并发明显增长后，再评估 ARQ 或 Celery。
- 当前不引入 Redis；如需任务队列和分布式能力时再统一评估。
