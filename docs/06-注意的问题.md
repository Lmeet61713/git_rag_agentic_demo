# 注意的问题

## 1. GitHub 登录

- GitHub OAuth 需要提前创建 OAuth App。
- 本地回调地址需要与 OAuth App 配置一致。
- 当前只访问公开仓库，不申请私有仓库权限。
- 以后访问私有仓库时需要增加 repo scope。
- OAuth 回调 URL 不要写死在代码里。
- Client ID 和 Client Secret 放入 .env。

## 2. 安全

- 不把 .env 提交到 Git。
- API Key 不保存在浏览器本地存储。
- API Key 由后端加密保存。
- 前端显示 API Key 时使用密码输入框。
- 用户应可以随时更换 API Key。
- 日志中不能打印 API Key。
- 日志中不能打印 GitHub token。

## 3. 向量数据库

- 不要按项目物理建多个 Chroma 数据库。
- 使用 metadata 做逻辑分层。
- Chroma metadata 字段不能任意嵌套。
- 图片不要直接对像素做 embedding。
- 图片描述存在误差，需要同时保留路径关键词。
- 没有代码专用 embedding 模型，必须用混合检索补偿。
- 向量库更新后必须记录 commit_sha 和 file_hash。

## 4. 代码和文档解析

- 不要盲目把代码转换为 Markdown。
- 代码保留原始语言和结构。
- 文档可以转换为 Markdown。
- 图片保留原文件。
- 忽略 .git、node_modules、dist、build 等目录。
- 大文件、二进制文件、压缩包默认跳过或单独处理。
- Windows 路径中注意反斜杠和编码。
- 中文内容必须统一使用 UTF-8。

## 5. Agent

- Agent 必须先检索再回答。
- Agent 回答必须带来源。
- Agent 不能把记忆内容当成真实代码。
- 短期记忆用于当前会话。
- 长期记忆用于用户偏好和项目事实。
- 长期记忆要按 user_id、project_id 隔离。
- 长期记忆要控制召回数量，不能全部塞进上下文。
- 模型调用失败时要有明确错误提示。

## 6. 模型配置

- DeepSeek 和阿里云模型名以官方文档为准。
- 用户指定的模型名需要做成可配置项。
- 不同服务商可能使用不同 API 格式。
- 后端需要统一适配层。
- API Key 更换后要清除旧的加密配置。

## 7. 异步任务

- 第一版不引入 Redis。
- 如果使用 FastAPI BackgroundTasks，要注意任务中断恢复。
- 任务状态要持久化。
- 索引失败时保留日志和可重试入口。
- clone 大仓库时要有超时和大小限制。

## 8. 增量更新

- 必须能识别文件是否变化。
- 必须能删除被删除文件的旧向量。
- 必须能识别仓库 commit 变化。
- 不能每次全量重建整个向量库。
- 更新失败时不能让旧索引损坏。

## 9. 前端

- 仓库列表需要支持分页。
- 未入库标签要明显，使用红色。
- 入库状态要实时反馈。
- 聊天窗口要区分代码、文档、图片。
- 图片要通过本地文件服务展示。
- 长代码要支持折叠和复制。
- 模型配置表单要支持更换 API Key。
